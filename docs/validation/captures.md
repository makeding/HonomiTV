## 表示・操作の契約

- ナビゲーションの `/captures/` から保存済み JPEG / PNG の一覧、ページ切替、更新日時順ソート、ファイル名・番組名・チャンネル名検索を利用できる。
- 既存の `capture.upload_folders` を読む。既存画像を移動・再登録する操作は不要。EXIF がない画像も表示する。
- 原図・サムネイル・メタデータ、ダウンロード、明示確認後の画像削除を提供する。画像が読めない場合はエラーと再試行を表示する。
- 個人フォルダはログインユーザーに属する。フォルダの削除や画像の取り外しでは画像ファイルを削除しない。
- 保存先の一時的な切断や外部削除で読めない画像は件数・一覧から除外するが、読み取り処理でブックマークを削除しない。
- 画像削除は管理者のみ。保存画像には過去のアップロード者情報がなく、推測による所有者判定はしない。
- 設定フォルダ外のファイル、シンボリックリンク、画像以外のファイルを取得・削除できない。
- 初回読み込み、空、失敗、再取得を区別し、失敗を「画像なし」に置き換えない。操作中は重複送信を抑止し、失敗時は入力を保持する。
- グリッドの画像枠とページ操作領域を予約し、再取得中も既存表示を維持する。狭幅では操作を折り返し、横スクロールやフォーカス喪失を起こさない。
- ルート変更後に古いレスポンスで一覧を上書きしない。確認対象を固定し、対象画面から離れたら古いダイアログを閉じる。

## 検証

- 既存スキーマのデータを保持したまま新規フォルダ用マイグレーションを適用できること。
- HTTP: 一覧・検索・ページング・画像・サムネイル、管理者削除、フォルダ CRUD と所有者分離、追加・取り外し、パストラバーサル拒否。
- UI: ナビゲーションからの到達、検索・並べ替え・ページ切替、原図表示・ダウンロード、フォルダ操作、確認・失敗・再試行、320px / 390px / デスクトップ。
- ローカルの自動テスト・ブラウザ確認と、ユーザー管理 API / 本番での動作確認は区別して報告する。

## 今回の検証結果 (2026-10-23)

- クライアント: ESLint、TypeScript、Captures 5 件 + ルーター 8 件の回帰テスト、production build が成功。
- サーバー: 実ルーターへの ASGI HTTP テスト 5 件が成功。一覧・検索・ページング・原図・ダウンロード・サムネイル・削除権限・フォルダ CRUD・所有者分離・追加/取り外し・既存ユーザーデータを残す migration を含む。Ruff / Pyright はエラーなし (既存の非推奨警告 10 件)。
- ブラウザ: 実 Vue ページをメモリ内 API fixture (40 枚の合成 JPEG、EXIF 相当情報あり/なし) に接続。デスクトップの一覧・2 ページ目・検索・失敗表示・原図、390px / 320px のグリッド、ログイン・フォルダ作成/変更・選択追加・フォルダ表示・画像削除確認のキャンセルを確認。
- 320px / 390px でキャプチャ画面の横方向オーバーフローなし。画像削除の確定はブラウザでは行わず、HTTP とコンポーネントのテストで検証。
- ユーザー管理の port 7000 API はローカルで稼働していないため、実保存画像や実 DB に接続した統合確認・migration 適用・デプロイは未実施。fixture の確認を本番動作の証明とは扱わない。
